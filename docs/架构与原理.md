# 架构与原理

## 设计约束

1. **零第三方依赖**：服务端只用 Python 标准库，能塞进工控机 / 边缘盒子。
2. **默认离线**：不内置任何远程地址，默认只连本机 Ollama。
3. **过程可验收**：每一步的输入、代码、输出、耗时都要能查。
4. **人在环**：步数有上限，高危命令拦截，不做无限自主循环。

## 关键机制

### 1. 多链路并行选路（`llm.auto_route`）

- 每条链路一个线程，同时 GET `{base}/api/tags`，记录 `(ok, ms)`。
- 按「可达优先、耗时升序」排序；上一轮选中的 base 若仍可达则优先复用（省一次抖动）。
- 返回 `{base, token, label, ms, candidates, at}`，`candidates` 供前端「链路自检」逐条展示。
- 链路列表来自 `R1_ROUTES` / `config/routes.json`；**默认只有 `http://127.0.0.1:11434`**。

> 这么做的现实原因：现场常同时存在「本机直连」「局域网网关」「远程备用」，写死任一条都会在某天挂掉。

### 2. Agent 主循环（`agent.py`）

```
用户消息 → 组装 messages（system_note + 历史）
       → 带 tools schema 调 llm.chat_stream
       → 若返回 tool_calls：逐个执行 → 结果回填 messages → 下一步
       → 若无工具调用：输出最终答案
       → 达到 max_steps（默认 8）或用户点「停止」即结束
```

- 支持 **Ollama 原生 tool-calling**；模型不支持时 `is_reasoner()` 判断后走文本协议降级。
- 推理型模型（`r1` / `qwq` / `think` / `reason`）的 `thinking` 字段单独渲染成「思维链」。
- 每一步通过回调把 `on_think` / `on_delta` / 工具结果推给前端，界面实时更新。

### 3. 工具集（`tools.py`）

| 工具 | 作用 |
|---|---|
| `list_dir` | 列目录，带类型/大小 |
| `read_file` | 按行区间读文件 |
| `write_file` | 写文件（原子替换） |
| `run_cmd` | 执行系统命令，带超时 |
| `run_python` | 执行 Python 代码，返回 stdout/stderr |
| `search_text` | 按 glob 递归搜文本 |
| `fetch_url` | 抓取 URL，输出长度受限 |

- `guard(cmd)` 拦截已知高危命令模式。
- `_trunc()` 统一截断输出，避免一条命令把上下文撑爆。
- ⚠️ **这不是沙箱**：工具以当前用户权限运行。

### 4. 流式协议

Ollama `/api/chat` 返回 NDJSON，逐行解析：

```
{"message":{"thinking":"..."}}     → 思维链
{"message":{"content":"..."}}      → 正文增量
{"message":{"tool_calls":[...]}}   → 原生工具调用
{"done":true}                      → 结束
```

`chat_stream()` 返回 `(正文, 思维链, 工具调用列表)`，错误以 `RuntimeError` 上抛。

### 5. 持久化

- `APPDATA/DGX-R1-Agent-Studio/config.json`：模型、温度、步数、工作目录、系统提示词、窗口尺寸。
- `APPDATA/DGX-R1-Agent-Studio/sessions.json`：会话历史。
- 写入用临时文件 + `os.replace()`，避免半截文件。
- 首次启动把 `web/seed_sessions.json` 的两条真实示例注入会话列表。

## 为什么不用常见技术栈

| 常见选择 | 不用的原因 |
|---|---|
| FastAPI / Flask | 多一个 pip 依赖，边缘部署就多一道坎；标准库 `http.server` 够用 |
| 前端框架 + 构建链 | 现场不需要热更新，原生三件套能直接改、直接看 |
| 向量库 / 长期记忆 | 本项目的目标是「看得见的单次执行」，不是知识库问答 |
| Docker 沙箱 | 部署成本翻倍；改为命令护栏 + 明确的权限告知（见 SECURITY.md） |

## 已知取舍

- 无并发任务队列：单用户、单会话串行执行。
- 无流式 SSE：前端通过轮询/一次性响应取状态（实现简单，局域网延迟可忽略）。
- 无权限体系：默认只监听 `127.0.0.1`。
